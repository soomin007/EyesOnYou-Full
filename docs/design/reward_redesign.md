# 위험/보상 축 개편 (2026-08-19 사용자 확정 · 구현 완료)

> 발단: "위험/보상 1/2가 있는데 2/2를 추천" + "저 내용들도 한 번 싹 엎어야"(2026-08-19).
> 진단: 종전 reward(1~3)가 risk와 사실상 1:1 상관(보상<위험 조합 1개뿐 · 3/3이 42%)이라
> 두 축이 정보를 못 줬고, 후반 풀은 전원 동점이라 추천이 셔플 순서로 떨어졌다.

## 1. 새 규칙

- **클리어 경험치 = 위험도 그대로**(r1=1 ~ r3=3). 위험할수록 항상 더 번다.
  "보상 같은데 위험만 높은" 열세 카드가 구조적으로 사라진다(가중치 가드 불필요).
- **보상 = 종류**(`reward_type`, RouteData 루트 필드):
  | 타입 | 카드 표기 | 효과 | 배정 기준 |
  |---|---|---|---|
  | `xp` | 경험치 | 클리어 XP +2 | 전투 밀도 맵 (17종) |
  | `record` | 기록 | 기록(덮어쓰기) 1칸 회복 · 가득하면 +2 XP 환산 | 기록·데이터 테마 (5종: 실험 구역·핵심부·서버 복도·통신 중계소·반응로 제어실) |
  | `recon` | 정찰 | 다음 구간 VEIL 마킹 강화(반경 2.5배 + 재밍·붕괴 블라인드 관통, 시각 마커 한정) | 감시·시야·우회 테마 (9종: 진입로·주차장·순찰로·감시탑·병동·검문소·???·통제실 복도·감시 회랑) |
  | `""` | - | 없음 | 탈출 5종(종착이라 지급 시점 없음 · 정직 산수) |

## 2. 추천(VEIL) 우선순위

① 고전/첫 판 → 최저 위험 ② 기록 소모 + record 루트 존재 → 그 루트(VEIL이 상태를 읽는 그림)
③ 능숙 → 최고 위험(=최대 XP · 동률이면 xp 종류) ④ 무난 → 위험 2 선호.
단일 후보 스테이지는 사유 공백(★ 없음) 유지. 사유 대사에 record 풀 3종 신설(REC_REASON).

## 3. 배선 지점

- 데이터: `RouteData.gd` ALL_ROUTES(reward_type) + `REWARD_TYPE_LABELS` + 추천 재작성
- 지급: `GameState.on_stage_clear`(risk XP + 종류 dispatch) · `last_clear_reward_note` 토스트
- recon 흐름: 클리어 `veilsight_recon_next` → 다음 `record_route_choice`에서 `_active` 승격
  (사망 재시도 포함 그 스테이지 전체 유효 · run.cfg 직렬화) → `VeilSight` 소비 ·
  발동 안내 자막 1회(`recon_note_pending`, Stage._ready seg0)
- 표시: RouteMap 카드 한 줄("보상 경험치")·범례·우측 패널 / HUD [고보상] 폐지([고위험]만)
- 구버전 호환: run.cfg/palimpsest의 옛 `current_route_reward` 키는 무시되고 기본값 ""로
  로드(버전 범프 없음 · 스냅샷 보존 우선)

## 4. 남은 튜닝(실플레이)

- record 루트가 s3~5 풀에 1종뿐이라 추천 ②가 자주 침묵 → 필요시 배정 조정.
- recon 체감(반경 2.5배가 과한지 · 재밍 관통이 재머 목표성을 죽이는지).
- XP 총량은 종전과 같은 체급으로 맞춤 · 본 캘리브레이션은 방 체인 확산 완료 후 일괄.
