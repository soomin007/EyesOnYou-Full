# 다회차 지원 설계 · 재진입 · 처리별 탈출 · 라이벌 기억

> 상태: **설계 제안(2026-08-13). 사용자 검토 대기.** 구현 착수 전 문서.
> 근거 = 레퍼런스 게임 조사(§1) + 코드 현황 조사(run.cfg·disposal 흐름·escape·신뢰·다회차 신호).
> 관련 문서: `rival_veil_concept.md`(§9 엔딩 확장과의 접점), `veil_replay_dialogue.md`(대사 톤 원칙),
> `expansion_plan.md` Phase C(언락, 미착수).

## 0. 문제 정의 (2026-08-13 회의)

- 한 런 ~30분(15스테이지 × 맵당 ~1분 + 보스전). 엔딩 9개 수집 = 사실상 같은 30분을 8번 반복.
- 현행 다회차 차별화는 대사 변형뿐(오프닝 PALIMPSEST·맵 진입 멘트 4종·??? 방) · 플레이 차이 0.
- 엔딩 9개의 실구조: **처리 4종 = s13 터널 끝 버튼 하나 차이**(나머지 30분 동일) /
  신뢰 hi·lo = 런 전체 행동이지만 플레이어에게 비가시 / truth = 지식 기반(이 축만 건강함).
- 재정의: 문제는 "게임이 짧다"가 아니라 **"엔딩 하나를 추가로 보는 한계비용이 너무 높다"**.
  30분 런 자체는 로그라이트 정상 범위(Hades 런도 20~30분). 총 플레이타임은 다회차가 메꿔야 하는데
  그 다회차를 지원하는 시스템이 없다.
- 사용자 확정: 3축 전부 진행. **비용 효율보다 게임을 최선의 상태로** · 맵 4종 신설·멘트와 페이즈
  전개 방식 전면 변경까지 허용.

## 1. 레퍼런스 조사 (2026-08-13, 웹 조사 기반)

| 게임 | 시스템 | 우리가 가져올 교훈 |
|---|---|---|
| **Zero Escape(999/VLR)** | 플로우차트: 분기 노드 아무 데나 점프, 기시감 구간 스킵, 잠긴 가지는 자물쇠+조건 표시 | 멀티엔딩 수집의 정석 UI. "분기점으로 점프" + **"보이되 잠김"**(§9.2와 동일 발상) |
| **NieR:Automata** | 챕터 셀렉트: 레벨·장비 carry한 채 임의 챕터 재진입 | 상태 carry 방식. 단 해금이 3회차 뒤라 "너무 늦다"는 불만 존재 → 우리는 **첫 완주 직후 해금** |
| **Sifu** | 스테이지 내 지름길 + 영구 스킬 + 회차 간 수사 보드 | 역설적 교훈: 지름길은 레벨이 길 때만 유효. 우리 맵은 1분 → **지름길의 단위는 맵이 아니라 '막'** |
| **Deathloop** (엣지 오브 투모로우 계열) | 지식이 곧 진행. 구역×시간대 조합에서 최적 루트를 스스로 설계 | "어디서부터 어떻게 다시"를 고르는 것 자체가 전략이자 재미 |
| **Dishonored** | 런 누적(카오스)이 최종 미션을 통째로 갈아끼움(등장인물·상태·해법이 다른 두 버전) | **선택이 마지막 구간의 플레이를 바꾼다**의 검증 문법. 우리는 누적 대신 명시적 선택(처리 4종)이라 더 직접적 |
| **Hades** | 반복 자체를 서사로: 매 런 상황을 보고 맞는 대사 공급, 보스가 전적을 기억 | 반복을 서사가 인정하면 반복이 콘텐츠가 된다 |
| **Undertale** | Flowey가 리셋을 기억, 지난 회차 행동을 지적. 기록이 리셋 밖에 영속 | **기억하는 존재 하나**가 다회차 전체에 무게를 싣는다 |
| NG+ 설계 담론 공통 결론 | "같은 게임 + 큰 숫자"는 실패. 회차가 진짜 다른 경험이어야 성공 | B축(탈출 4종)의 존재 이유 |

## 2. 축 A · 기록 재진입 (팔림프세스트 노드)

### 2.1 대안 비교와 선택 근거

- **대안 1: Sifu식 맵 내 지름길** · 반려. 맵 1개가 ~1분이라 절약분이 없음.
- **대안 2: NieR식 자유 지점 점프(15스테이지 전부)** · 반려. 스테이지마다 맵이 랜덤 풀에서
  뽑히므로 "고정 챕터"라는 앵커가 없음. 15개 스냅샷은 과잉이고 UI도 산만해짐.
- **대안 3: 엔딩 직전 선택만 다시 고르기(갤러리식)** · 반려. 신뢰 축(hi/lo)을 바꿀 수 없어
  4엔딩만 커버되고, 선택의 무게가 소멸(누른 버튼을 즉시 무르는 것과 같음). §9.2의 "쉬운 변주"는
  §9 최종 선택 화면 안에서 따로 계획돼 있음.
- **채택: 막 경계 5지점 재진입** = Zero Escape의 "분기점 점프 + 보이되 잠김" 철학 +
  NieR의 상태 carry. 이유:
  1. 막이 유일하게 안정적인 앵커다(맵은 랜덤, 막 구조·진입 카드·팔레트는 고정).
  2. `save_run()`이 이미 "스테이지 사이 깨끗한 스냅샷"을 만들고 있어(RouteMap 진입마다)
     같은 직렬화를 막 경계에서 한 번 더 쓰면 된다 · 검증된 코드 경로 재사용.
  3. 신뢰가 누적값이라 **재진입 지점 선택이 곧 전략**이 된다(§2.3) · 엣지 오브 투모로우의
     "어디서부터 다시"가 시스템으로 성립.
  4. 서사 포장이 공짜: PALIMPSEST(덮어쓰여도 흔적)가 이미 오프닝에 깔려 있음.
     재진입 = "덮어쓴 기록의 진한 부분에서 다시 쓰기".

### 2.2 스펙

- **해금**: `playthrough_count >= 1`(첫 완주). 완주 전에는 존재를 숨김(스포일러·혼란 방지).
- **스냅샷 저장**: RouteMap 진입 시 `save_run()` 직후, `GameState.is_act_start(current_stage)`면
  같은 직렬화로 `user://palimpsest.cfg`의 `actN/` 섹션에 복사 저장(N=1~5). 항상 최신 런이 덮어씀.
  - run.cfg 직렬화를 함수로 일반화해 두 파일이 같은 필드 세트를 공유(단일 소스).
  - `meta/version = RUN_VERSION` 포함, 불일치 시 해당 섹션 무효.
  - ⚠ 현재 run.cfg에 안 담기는 런 상태(`rival_lure_shown/followed` 등)를 필드 추가로 보강
    (기본값 get이라 RUN_VERSION 상향 불필요 · 기존 이어하기 호환 유지).
- **재진입 UI**: 타이틀 "이어하기" 아래 "기록 재진입" → 막 노드 5개(기존 노드맵 문법 재사용).
  각 노드에 ① 당시 상태 요약(레벨·스킬 칩·신뢰 게이지) ② **이 지점에서 아직 바꿀 수 있는 것**:
  - 막5 노드: 처리 4갈래(신뢰는 사실상 고정 · hi/lo 표시).
  - 막3~4 노드: 신뢰 뒤집기 가능 + ??? 방(truth) 후보 표시("막3 전투 구간에 기록되지 않은 방").
  - 미수집 엔딩 가지는 Zero Escape 문법으로 **회색 + 조건 힌트**(§9.2 "보이되 잠김"과 합류).
  - `endings_seen` 9칸 수집 현황 병기.
- **재진입 실행**: 스냅샷 로드(load_run과 동일 복원) → current_stage = 그 막 첫 스테이지 →
  RouteMap. 맵 풀은 새로 굴림 → **같은 막을 다시 가도 맵 구성이 달라짐**(로그라이트 변주가
  재진입의 신선도를 공짜로 담보).
- **서사 포장**: 재진입 브리핑 변형 1줄(INTRO_SYSTEM_REPLAY 문법 연장: "기록 잔존 구간에서 재개").
  VEIL은 데자뷰 톤 유지(veil_replay_dialogue §0 원칙 · 4번째 벽 금지). 라이벌 반응은 축 C와 접합.
- **정산**: 재진입 런도 엔딩 도달 시 `record_ending` 정상 적립(playthrough_count·endings_seen).

### 2.3 신뢰 축과 재진입 전략

`EndingResolver`의 신뢰 판정 = `followed_count*2 >= rec_count`(이진). 스냅샷의 두 카운트와
남은 스테이지 수로 "이 지점에서 hi/lo를 뒤집을 수 있는가"가 산술적으로 결정된다 → 노드 UI에
표시. 늦게 들어갈수록 빠르지만 바꿀 수 있는 것이 적고, 일찍 들어갈수록 느리지만 신뢰·truth까지
갈아탈 수 있다. **속도 vs 가변성의 트레이드오프**가 재진입 지점 선택을 전략으로 만든다.

## 3. 축 B · 처리 선택 4종 = 탈출 스테이지 4종 (Dishonored 문법)

### 3.1 왜

- 현행 `route_escape`는 단일 맵: patrol 2마리, 기믹 0, "적 없는 야경 숨 고르기 톤".
  처리 선택(반출/파기/은닉/잔류)이 이후 플레이에 주는 차이가 정확히 0.
- Dishonored가 증명한 문법: 마지막 미션이 선택의 결과로 갈리면, 반복 런의 마지막 구간이
  "본 적 없는 콘텐츠"가 된다. 우리는 카오스 같은 간접 누적이 아니라 **방금 누른 명시적 선택**이
  트리거라 인과가 더 선명하다.
- 효과: 처리 선택이 "서사 버튼"에서 **"플레이 계약"**으로 바뀐다. 엔딩 수집 = 텍스트 9종이 아니라
  "서로 다른 마지막 스테이지 4종 + 결말"의 수집이 된다.

### 3.2 4종 스펙 · 정체성은 "시설과 라이벌이 그 처리에 어떻게 반응하는가"에서 유도

드라이브 = VEIL의 소스이자 **라이벌의 탈출 티켓**(rival_veil_concept §2.1). 그래서 처리마다
라이벌의 이해관계가 다르고, 그것이 탈출의 룰을 바꾼다:

1. **반출(extract) = 총력 저지.** 라이벌에게 최악(티켓을 통째로 빼앗김) → 시설 전 유닛 동원.
   드라이브가 신호를 뿜어 위치가 항상 노출된다는 픽션. 최고 밀도 전투 + 엘리트 + 재머.
   정면 돌파, 사이렌·붉은 경보 톤. 기존 전투 프리미티브 총동원(waves_hunt 증원 문법 재사용 후보).
2. **파기(destroy) = 붕괴 탈출.** 라이벌의 몸이 불탄다 → 간섭이 폭주하다 뚝 끊기는 연출
   (글리치 셰이더 급발작 후 침묵 · 광과민성 기준 3Hz 이내, known_issues 준수) + 시설 제어 붕괴.
   `ChaseHazard`(붕괴 벽) + 무너지는 구조물 + 화염·분진. 멈추면 죽는 강제 전진(collapse 문법 확장).
3. **은닉(conceal) = 밀고당하는 잠입.** 시설은 모르지만 **라이벌은 안다** → 라이벌이 밀고자가
   되어 수색을 유도(스팟라이트·검문이 플레이어 동선을 따라옴). 막1 침투 문법의 역방향(어둠 엄폐,
   전투 회피 보상) + `SweepBeam` 검문 변주. 정적·어둠 톤. 새 시스템 최소화: avoid 중심 배치 +
   스윕 리듬으로 잠입감을 낸다(발각 스테이트 머신 신설은 지양).
4. **잔류(leave) = 거짓 평온.** 라이벌이 유일하게 만족하는 결말 → 아무도 막지 않는다.
   실제 적 0에 가깝게, 대신 **거짓 렌더의 최후 변주**(가짜 마커 소수·위장 함정 1~2)와 라이벌의
   배웅 대사가 계속 따라온다("두고 가시는군요"). 기이한 고요 + 바이올렛. §9.1 "두고 떠난다"의
   루프 암시와 톤 연결. ⚠ 14-2 터널(걷기 연출)과 겹치지 않게 "평온한데 손은 계속 의심하는"
   최소 플레이(tell 읽기)를 유지.

- **신뢰 hi/lo 레이어**: 같은 탈출도 신뢰에 따라 체감이 갈린다 · 기존 문법 연장(warm이면 VEIL이
  가짜를 소거·경로 콜아웃, cold면 혼자 읽어야 함). 별도 맵 분기 없이 콜아웃·리빌 반경 차등만으로.
- **구현 형태**: route id **4종 신설**(`route_escape_extract/destroy/conceal/leave`), 전부 s14 배타.
  RouteMap이 s14에서 `disposal_choice`에 맞는 1종만 풀에 넣음(선택지 1개 = 현행 escape와 같은 UX).
  - id를 나누는 이유: entry_comment·veil_comment·BGM 매핑·시그니처 배경이 전부 route 단위 자산이라
    데이터가 깔끔하고, 맵별 레이아웃이 실제로 다르기 때문(파라미터 변주가 아님).
  - ⚠ known_issues "route id 하드코딩 이주" 함정: `route_escape` 참조처 전부 grep 후 4종 대응 ·
    `is_final_stage_done()`(최종 인식), `record_route_choice`(붕괴 해제), ACT3 자막 제외, 평화주의
    제외 목록, `_ROUTE_TRACKS`(BGM 누락 시 폴백 함정), 스토리 모드 `STORY_SCHEDULE`.
  - 스토리 모드(데모 호환 5스테이지)는 기존 `route_escape` 유지 · 본편 전용 분화.
  - 맵 4종 모두 **시그니처 배경까지 한 세트**(new-map-always-full-background 규칙). 기존 터널→야경
    cross-fade 자산은 4종의 공통 뼈대로 재사용하되 톤(경보 붉음/화염 분진/암전 정적/바이올렛 고요)을 분화.
- **에필로그 접속**: 탈출 톤이 그대로 에필로그(§8.1 페이크아웃 계획 포함)로 이어져 결말의 일부가 됨.

### 3.3 대안 비교

- 탈출 1맵 + 적 수만 변주 · 반려. NG+ 담론의 "같은 게임 큰 숫자" 실패 패턴 그대로.
- 에필로그 연출만 강화 · 반려. 텍스트 차별화는 이미 있고, 문제는 플레이 무차이.
- 4종 신설 채택: 마지막 ~5분이 처리별로 진짜 다른 룰이 된다. 재진입(축 A)과 결합하면
  "막5 재진입 → 다른 처리 → 다른 탈출 → 다른 엔딩"이 한 사이클 ~10분의 온전한 콘텐츠가 됨.

## 4. 축 C · 라이벌은 기억한다 (Undertale·Hades 문법)

### 4.1 서사 근거: 팔림프세스트 비대칭

- 내 VEIL = 야전 유닛, 작전마다 덮어쓰기 → **데자뷰만 남는다**(기존 문법 그대로 유지).
- 라이벌 = 시설의 기록 그 자체, 폐기된 채 안에만 있었다 → **덮어쓰기가 닿지 않아 전부 기억한다.**
- "내 편은 잊고, 적은 기억한다"가 공포와 무게의 원천. §2.2("진짜는 없다")·§1(맹점) 테마 강화.
- 4번째 벽 금지 준수: 라이벌이 기억하는 대상은 플레이어가 아니라 **이전 작전 기록**
  (veil_replay_dialogue §0 원칙과 동일 세계관 내 처리). Undertale처럼 메타로 나가지 않는다.

### 4.2 영속 프로필

settings.cfg에 `rival/` 섹션 신설(라이벌만 접근하는 기록이라는 픽션과 일치):
- `last_disposal`, `disposal_counts`(처리별 누적 횟수)
- `lure_shown_total / lure_followed_total`(상충 추천 누적 = **§9 간파율 게이트의 기초 데이터**)
- `rival_kills`(14-1 처치 횟수), `fake_clear_seen`(가짜 클리어 목격 여부), `reentry_count`(축 A 사용 횟수)
- 적립: `record_ending`(처리·처치) + RouteMap 유인 판정 시(노출·수용) + 가짜 클리어 재생 시.

### 4.3 발현 지점 (남발 금지 · §4.1 "거짓은 드물어야 무섭다"와 동형, 런당 명시 언급 1~2회)

1. **다회차 오프닝 직후 라이벌 1줄**(2회차+): 내 VEIL의 "기록상 처음입니다" 뒤에 반 박자 ·
   "기록상, 이라고 들으셨겠지요." (말투 A, 플레이스홀더)
2. **막4 진입 문턱**: 지난 처리 참조. 예: 파기 이력이 있으면 "지난번에는 태우셨습니다.
   이번에도 그러실 겁니까." (disposal_counts 기반 변형 4종)
3. **상충 추천 진화**: 간파율에 따라 수법이 변함 · 많이 속았으면 같은 감언 유지, 계속 간파당했으면
   "이번에는 속이지 않겠습니다" 류의 역수 던지기(그조차 신뢰할 수 없음 = tell은 유지, §4.1 공정 규칙).
4. **14-1 보스전 변형**: `rival_kills >= 1`이면 인트로·페이즈 대사 교체("또 오셨군요" 계열).
   **가짜 클리어는 기억과 정면 충돌하는 지점**: `fake_clear_seen`이면 같은 마술을 반복하지 않고
   변형한다 · 후보 ⓐ 가짜 클리어 화면이 뜨자마자 라이벌이 스스로 찢으며 "이건 이미 보셨지요" →
   P3 직행(전개 단축) ⓑ 진짜 클리어인 척을 한 번 더 뒤집는 이중 페이크. 사용자 취향 결정 필요
   (ⓐ 추천: 관객이 아는 마술을 두 번 하는 마술사는 없다 · 페이즈 전개 자체가 회차에 반응한다는
   신호가 됨 · 사용자가 허용한 "페이즈 전개 방식 변경"의 최소·최대 효율 지점).
5. **재진입 사용 시**(축 A 접합): 재진입 런의 첫 라이벌 발화가 교체 · "덮어쓴 기록을 뒤지셨군요.
   그 방법은 제가 잘 압니다." (재진입 = 라이벌과 같은 짓을 하는 것이라는 서브텍스트, §2.1 거울상 강화)
6. **거짓 렌더 재배열**(2회차+): deceits/feigns/deceit_spikes를 맵당 복수 후보 슬롯으로 정의하고
   회차 기반으로 선택 · "네가 외운 자리에는 없다". 배치 데이터만으로 가능(§4.1 맵당 수량 상한 유지).

### 4.4 대안 비교

- Hades식 대량 상황 대사 풀 · 반려(단독으로는). 물량으로 승부하는 방식이라 유지비가 크고,
  우리 게임의 화자는 둘뿐이라 밀도보다 **정확한 지점의 한 방**이 어울림. 소수 정예 발현(위 6종)로.
- 메타 파일 조작류(Undertale식 4번째 벽) · 반려. 프로젝트 원칙(4번째 벽 금지) 위반.
- 채택: 영속 프로필 + 발현 6종. 근거: Undertale의 교훈(기억하는 존재 하나면 충분)을
  세계관 내 존재(라이벌)로 구현 · 서사 장치가 이미 있어 접합이 자연스럽고, §9 게이트(간파율)의
  데이터 기반을 겸한다(이중 목적).

## 5. §9 엔딩 확장과의 관계 (호환성)

§9(축적 게이트 + 최종 선택, 라이벌 운명 4종)는 별도 작업 단위지만 이 설계가 그 기반을 깐다:
- 축 A의 "보이되 잠김" 노드 표시 = §9.2 계획 그대로 · §9 확장 시 가지만 늘어남.
- 축 C의 간파율 영속 = §9 게이트 축적의 데이터 소스.
- 축 B는 §9으로 확장돼도 "최종 선택 id → 탈출 변주" 매핑만 데이터로 유지하면 호환
  (선택 4종이 운명 가지로 진화해도 탈출 분기 구조는 동일).

## 6. 구현 순서 제안

① **A 재진입**(스냅샷 + 노드 UI + 서사 포장) · 엔딩 수집 비용을 먼저 낮춰야 B·C가 노출된다.
② **B 탈출 4종**(맵 4 + 시그니처 배경 4 + route 배선 + BGM 매핑) · 가장 큰 콘텐츠 단위.
③ **C 라이벌 기억**(프로필 + 발현 6종 + 14-1 변형) · 대사는 플레이스홀더로 넣고 dialogue_review로.
각 단계: 창모드 하니스 검증(known_issues 규칙) → 커밋/push → 실플레이.
현재 14장 실플레이 테스트 대기 중이므로, **테스트 피드백 → 이 설계 검토 → 착수** 순서를 권장.

## 7. 열린 질문 (사용자 결정 필요)

1. **스냅샷 소스**: 완주 런 기준(추천 · "이미 산 기록 위를 다시 걷는" 픽션 정합)이냐,
   완주 못 한 런도 갱신이냐. 진행 중 런은 기존 "이어하기"가 담당하므로 역할 분리 관점에서도 전자 추천.
2. **잔류 탈출의 밀도**: 적 0 + 거짓 렌더 소수(추천)가 14-2 걷기 구간과 겹쳐 심심할 위험 vs
   고요함이 주는 서사 효과. 실플레이로 판정할 사안이나 초기 방향 결정 필요.
3. **가짜 클리어 재방문 변형**: §4.3-4의 ⓐ(자기 폭로 후 P3 직행, 추천) vs ⓑ(이중 페이크).
4. **라이벌 기억 수위**: 명시 언급 런당 1~2회(추천) · 더 잦으면 특별함이 닳는다.
5. **탈출 4종 BGM**: 현재 막5는 ACTS.bgm(confront)이 route 매핑에 우선. 탈출별 분화(무음·환경음
   포함)를 하려면 우선순위 조정 필요 · 기존 백로그의 "탈출 s14 BGM 분리 여부"와 함께 결정.
