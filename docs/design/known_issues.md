- **`bool(null)` 호출 금지 · "Nonexistent 'bool' constructor" 크래시(런타임, `int()` 함정과 동형).**
  `bool()` 자체는 정상이지만 인자가 **null**이면 Nil→bool 생성자가 없어 죽는다. `Object.get("prop")`는
  속성이 없으면 *기본값 없이 null*을 반환하므로, `bool(node.get("harmless"))`처럼 존재를 보장 못 하는
  속성을 `bool()`로 감싸면 그 노드에서 크래시(런타임 에러가 함수 실행을 중단 → 이후 로직 전부 스킵).
  → 존재 불확실 속성은 `bool()` 없이 **truthiness**로: `if node.get("prop"):`(null은 falsy, 안전). 또는
  기본값 있는 dict는 `bool(d.get("k", false))`(get에 default가 있으면 null이 안 나와 안전). (2026-07-03
  DefenseCore가 "enemy" 그룹의 harmless 속성 없는 더미 노드에서 크래시 · `--import`는 통과, **창모드
  부팅에서만** 잡힘. 함수 본문 런타임 에러는 import 캐시가 놓친다는 기존 교훈 재확인.)
  **재발(2026-08-20)**: FallingDebris 적 판정을 TrainHazard에서 복사하며 `bool(en.get("harmless"))`
  패턴까지 복사 → lab 잔해가 "enemy" 그룹의 **BossSentinel**(harmless 속성 없음)을 스캔해 에디터째
  사망(사용자 실플레이 중단). 교훈: **규칙이 있어도 복사 원본이 위반이면 재발한다** · 기존 코드를
  템플릿 삼을 때도 known_issues 패턴 검사를 통과시킬 것. 방지책: "enemy" 그룹을 도는 데미지 루프는
  ⓐ `enemy_type == null` 게이트로 일반 Enemy만(보스·더미 제외 = 크래시와 "보스가 자기 해저드에
  맞는" 설계 오류 동시 차단) ⓑ 속성 접근은 truthiness. TrainHazard 원본도 소급 수정(2026-08-20).

- **`int(배열)`/`int(딕셔너리)` 호출 금지 · "Nonexistent 'int' constructor" 크래시.**

  → 컬렉션 크기는 `arr.size()`. 같은 데이터를 여러 경로에서 셀 땐(enemies/waves) 동일 패턴 유지.

## 게임 설계 함정

- **구조/스토리 발화는 컷씬(StoryDialogue)으로 · 흐르는 자막 + "적만 멈춤" 유예는 둘 다
  반려됐다.** 경위: 2026-08-17 P2 "어두워지고 뿅뿅대서 설명을 읽을 수 없다" → 온보딩 유예를
  만들고도 P1 인트로·P3 개시·잠금 비트엔 안 깔아 2026-08-23 "대사가 전투랑 겹쳐 읽을 수가
  없다" 재발(동형 미스윕). 이어 "적 정지 유예"로 고쳤더니 **"적은 가만히 있고 플레이어가
  기습하는 게 정답이 돼버린다" + "여러 줄이 줄줄이 나오면 가독성이 떨어진다"**로 같은 날 재반려.
  → 확정 문법: 구조/스토리 비트(보스 오프닝·페이즈 전환·reveal·잠금·격파)는 `StoryDialogue`
  컷씬(세계 일시정지 · 한 줄씩 · 스페이스 진행 · ESC/길게 누르기 건너뛰기)으로 낸다. 새 각본
  발화를 넣는 커밋은 컷씬인지 자막인지 먼저 판정할 것. 자막이 맞는 쪽: 조우 직전 위협 콜아웃·
  전투 중 조언·route_lines(눈앞의 것이 지시 대상 = 겹침이 정상). 보조 도구(컷씬 앞뒤 무대
  정리): 개시 유예(스폰 지연·intro_hold·`_state_t` 음수 시드) · 조용한 창(`_combat_near_player`
  폴링 + 상한 · 전투 한복판 컷씬 팝 방지). 함정 2건: pause 중에도 process_frame은 돌므로
  await 폴링 가드는 `StoryDialogue.active`를 봐야 한다(lab reveal 14s 상한) · 검증 드라이버는
  PROCESS_MODE_ALWAYS가 아니면 컷씬 pause에 같이 멈춘다.

- **체류 시간·조우 횟수는 최고 속도 하한으로 계산할 것 · "전투로 느려진다" 배수 금지.**
  지하철 선로 방을 "주파 ~30초에 열차 4~5회"로 문서화했으나 실플레이는 2회(사용자 2026-08-17
  "왜 자꾸 체류 시간을 과대평가하는지 이해가 안 돼"). 원인 둘: ⓐ 플레이어는 SPEED 240 +
  대시 720으로 직진하고 선택 전투는 스킵하는데 추정에 전투 정지 배수를 얹음 ⓑ 주기 이벤트의
  실주기를 interval만 보고 계산(열차 실주기 = interval 6.5 + 예고 2.2 + 통과 2.6 = 11.3초).
  규칙: 체류 하한 = 길이 ÷ 240(대시 감안 −15%) · 조우 수 = floor(하한 ÷ 실주기, 상태 머신
  전 단계 합산) · 수치 주장엔 계산식을 주석으로 남김 · 횟수 보장이 필요하면 주기식이 아니라
  **위치 트리거**로 설계 · 가능하면 [RUN] 실측 후 확정.

- **배경·목표물에 등간격 수직 기둥(마스트) 반복 금지 · "그놈의 기둥" 습관.** 실내 공용 배경이
  360px마다 바닥~천장 기둥을 깔고, 그 위에 맵별 기둥(스크린도어 기둥·터널 아치 리브)과 보스
  목표물 마스트(P1 안테나·P2 소형 안테나)까지 겹쳐 "맵이 다 똑같다 + P1/P2가 똑같다"로 읽힘
  (사용자 2026-08-17 "네 고집을 버리는 게 작업 1순위"). 규칙: ⓐ 새 배경의 기본 어휘에서
  등간격 수직 스트라이프 금지, 맵 정체성 모티프(수평선·곡선·바닥 디테일)를 먼저 ⓑ 페이즈
  목표물은 실루엣 어휘를 페이즈마다 바꿈(수직 마스트 다음은 낮은 돔/수평 소켓) ⓒ 전투 동선의
  솔리드는 몸통 높이 이상 + 명확한 외곽선 · 무릎 높이 솔리드는 탄만 먹는다(방1 잔해 사건).

  "격벽 뒤는 소거를 피합니다"라고 썼다가 반려(사용자 2026-08-17 "플레이어가 알아들을 수가
  없잖아. 네 마음대로 단어 지어내지 말라고"). 격벽·소거·실체화 창·동기 같은 설계 용어는
  코드/문서 내부용이고, 대사는 플레이어가 화면에서 본 것의 일상어로만(올라온 벽 · 훑고

  없음", 연출은 자막뿐이라 밋밋. → 재설계 원칙: ⓐ 엔드게임 전투는 **만렙 빌드 기준으로** 설계

  연출의 임팩트는 사운드·화면 킥·완만한 블룸 램프로 낸다. 넓은 면적을 채우는 글로우의 맥동도
  진폭을 얕게(±5% 안팎)·느리게 · 화면 대부분을 차지하는 발광체가 ±15%로 출렁이면 "번쩍번쩍"으로
  읽힌다. 기존 연출 점검 시에도 이 기준으로 훑을 것(보스 글리치 복선·재머 비네트 등).

- **적/플레이어의 지속 틴트를 `visual.modulate`/`self.modulate`에 걸면 텔레그래프·피격·부활 플래시가 흰색으로
  덮어쓴다 · 독립 오라 자식으로 표현하거나 리셋 대상을 그 틴트로 바꿀 것.**

  흰색이 아니라 그 틴트 값(예: `_skin_tint`)으로** 바꾼다(코나미 스킨은 부활 플래시 tween 목표를 흰색→`_skin_tint`).
  투명도(`modulate.a`)만 바꾸는 코드(invuln 깜빡임)는 RGB 틴트를 보존하므로 무관. (2026-07-04 이스터에그.)

- **하드코딩된 목록(연습장 맵 등)은 단일 소스(RouteData.ALL_ROUTES)에서 파생 · 콘텐츠 추가 시 자동 반영.**

  Briefing 등은 루트가 full-rect Control이라 탭(emulate 마우스)이 gui_input에서 소비돼 `_unhandled_input`에
  ScreenTouch가 안 온다. 키(jump)는 UI가 안 먹어 데스크톱에선 정상이라 놓치기 쉽다(사용자: "튜토는 되는데
  오프닝 멘트가 안 넘어감"). → 터치 진행이 필요한 화면은 `_input`으로(UI 소비 전에 받음). 자체 클릭 버튼이
  있으면 그 상태에서 return해 버튼 gui_input으로 넘긴다.

- **모바일 웹은 데스크톱 비율(1280×720) UI를 그대로 렌더해 버튼·글씨가 작아 누르기 어렵다.**
  stretch/expand는 해상도만 맞출 뿐 UI 물리 크기를 안 키운다. 폰 작은 화면에선 메뉴/설정 버튼이 너무
  작았다(사용자 보고). → 터치 기기에서 `get_window().content_scale_factor`를 올려 확대(메뉴 1.4 / 인게임
  1.1, 씬 그룹으로 분기). 인게임은 월드도 같이 커지니 밸런스 고려해 낮게.

  "가로로 돌려주세요" 안내로 폴백. fullscreen 대상은 `canvas`보다 `document.documentElement`가 안정적.

- **`emulate_mouse_from_touch`(기본 true)로 화면 탭은 좌클릭도 합성한다 · is_tap과 좌클릭을 둘 다 처리하면 2회 발동.**

  `MOUSE_BUTTON_LEFT`을 모두 인정하는 화면(ArcturusDocumentOverlay: 줄 진행/닫기)은 한 탭에 2줄이 넘어간다.
  `set_input_as_handled()`는 *다른* 합성 이벤트를 막지 못한다(별개 이벤트). Briefing류는 좌클릭을 안 다루고
  jump/is_tap만 봐서 무사했음. → 좌클릭 분기에 `not OrientationGuard.is_touch_device()` 가드를 달아
  터치 기기에선 is_tap 경로만 쓴다. emulate 자체는 메뉴 버튼 탭에 필요하니 끄지 말 것(2026-07-02).

- **process_mode=ALWAYS 오버레이를 `show_doc()` 없이 add_child만 하면 _process가 미생성 노드에서 null 크래시.**
  검증 하니스가 `ArcturusDocumentOverlay.new()`+`add_child`만 하고 `show_doc(lines)`를 안 부르면, `paper`가
  아직 null인데 _process(line166 `paper.position`)가 돌아 "property 'position' on Nil"이 뜬다. 실게임은

  함수까지 호출**해 검증할 것(안 그러면 하니스 인공물을 실버그로 오판). (2026-07-02 터치 검증에서 관측.)

## 런타임 (상세: 메모리 project-runtime-safety)

- **paused / Engine.time_scale carry로 인한 freeze.**
  `get_tree().paused`는 SceneTree 전역이라 scene 전환에 carry된다. overlay/도전방 등에서 paused 해제
  누락 시 다음 scene이 freeze. 새 overlay/scene 추가 시 paused 해제 안전판을 같은 패턴으로 둘 것.

- **pause를 거는 모달(도감·레벨업)이 연출 체인 도중에 뜨면 pausable 타이머 체인이 동결되고,
  모달 레이어가 연출 레이어보다 아래면 보이지도 않는다.** 14-1 가짜 클리어(레이어 44, 타이머
  전부 process_always=false) 중 P2 재머 노드의 도감 첫 조우 팝업(45, pause)이 뜨면 입력 전까지
  체인 정지 = "P2→P3 전환 안 됨"(하니스 재현 2026-08-14). 레벨업 오버레이(구 40)는 44 **아래**
  숨어 pause만 걸린 정지 화면이 됐다. → ① 보스 목표물(rival_node)은 도감 조우 제외 ② 모달
  레이어는 스테이지 연출 레이어(44)보다 위로(레벨업 46) ③ 연출 타이머 체인 하니스는
  `get_tree().paused`를 diag에 반드시 포함(이번 발견 경로).

- **시간 구동 풀스크린 연출(글리치 등)은 pause를 명시적으로 다뤄야 한다 · 안 그러면 피크에서
  얼어붙은 화면이 pause 내내 남는다.** 14-1 글리치 도중 레벨업(트리 pause)이 뜨자 `_GlitchRunner`
  (기본 PAUSABLE)가 멈춰 최대 강도 왜곡이 레벨업 화면을 덮은 채 정지(사용자 보고 2026-08-14,
  "매우 눈 아픔"). → 엔벨로프 러너는 `PROCESS_MODE_ALWAYS` + pause 중 빨리 감기(3배속)로 스스로
  정리되게. 새 풀스크린 연출을 만들면 "이 도중 pause가 오면 화면이 어떻게 남는가"를 항상 검사.

- **검증 하니스가 Stage를 *단독* 부팅하면 `get_tree().paused=true`로 시작 → `_physics_process` 안 돈다.**
  실제 게임은 Briefing._ready가 `paused=false`로 풀고 Stage로 오지만, 래퍼에서 Stage.tscn을 직접
  인스턴스화하면 그 해제를 건너뛰어 트리가 paused로 남는다. 그러면 이동 발판(MovingPlatform) 등
  `_physics_process` 구동 요소가 첫 프레임만 돌고 멈춰 "안 움직인다"로 오판된다(2026-06-26 MovingPlatform
  검증에서 dx=0으로 나와 메커닉 버그로 오해할 뻔). → **Stage 단독 부팅 검증은 `add_child` 직후
  `get_tree().paused = false`를 명시**해 실게임 조건(unpause)을 만들 것. (메커닉이 unpause에서 정상이면
  실게임에서도 정상.)

- **트리에서 빠진 노드의 콜백/틱이 `get_tree()`를 쓰면 null 크래시.**
  플레이어 사망 → 씬 전환 중, 아직 free 안 된 적의 tween/timer 콜백이나 한 프레임 늦은 틱이
  `get_tree().get_nodes_in_group(...)`를 호출 → "Cannot call method ... on a null value"(Enemy.gd, 2026-06-09).
  → 트리 접근(`get_tree()`/`get_world_2d()`/`get_parent()`) 전에 null 가드. player 조회처럼 자주 쓰는
  접근은 **단일 헬퍼**(`_find_player`)에 가드를 모아 모든 호출처를 한 번에 보호. `_physics_process`엔
  `is_inside_tree()` 가드를 더해도 저렴.

- **`get_tree().paused=true` 중엔 PAUSABLE 노드가 입력 콜백(`_input`/`_unhandled_input`)을 못 받는다.**
  pause는 `_process`뿐 아니라 입력 처리도 막는다. 그래서 "ESC로 자기 일시정지 메뉴를 *열고 닫기*"를
  PAUSABLE 호스트(RouteMap/Stage)의 `_unhandled_input`에 두면, 연 뒤(paused=true)엔 닫는 ESC가
  호스트에 도달하지 않아 안 닫힌다(헤드리스 재현 확인, 2026-06-15). → 메뉴 *씬*(게임 로직 없는 RouteMap)은
  `process_mode = PROCESS_MODE_ALWAYS`로 둬 paused 중에도 ESC를 받게. Stage처럼 ALWAYS로 못 두는
  게임플레이 호스트는 ESC는 열기만, 닫기는 "계속하기" 버튼(ALWAYS)에 맡기는 게 현재 동작.
  ALWAYS로 둘 땐 `_input`이 paused 중 SPACE를 소비하지 않게 가드(일시정지 메뉴 버튼 ui_accept 보호).

- **헤드리스 `-s` SceneTree 스크립트에선 오토로드가 컴파일 타임에 안 보일 수 있다.**
  `godot --headless -s test.gd`로 `GameState` 등 오토로드를 직접 식별자로 쓰면 "Identifier not found"
  컴파일 에러(2026-06-15). 오토로드가 필요한 런타임 검증은 **래퍼 .tscn(Control)을 창모드로 실행**하면
  오토로드가 정상 초기화된다. `Input.parse_input_event`로 ESC 등 액션을 주입해 동작을 관찰할 수 있다.
