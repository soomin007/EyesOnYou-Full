## 요약
웹 플레이 시 백그라운드 탭 오디오 음소거를 본편(EyesOnYou-Full)과 데모판(EoY) 두 프로젝트에 적용.
숨은 탭에선 GDScript가 정지하고 오디오만 계속 재생되는 문제라, 엔진이 아니라 페이지 JS(head_include)로 처리.

## 주요 변경
- `EyesOnYou-Full/export_presets.cfg` — Web 프리셋 `html/head_include`에 음소거 스크립트 추가 (커밋 79c5e10)
- `EoY/export_presets.cfg`(데모, 별도 repo soomin007/EyesOnYou) — 동일 스크립트 추가 (커밋 eff1edf)
- 스크립트: AudioContext 래핑 후 `visibilitychange`에서 탭 숨김=suspend / 복귀=resume.
  godot-web-mobile 스킬 §3의 검증된 한 줄 스크립트를 그대로 사용(내부 홑따옴표만 써서 cfg 이스케이프 회피).

## 결정 사항
- 엔진 내(GDScript)가 아니라 `head_include`(페이지 JS)로 처리 — 숨은 탭은 requestAnimationFrame이 멈춰
  Godot 메인 루프째 얼어붙고 오디오만 독립 재생되므로, 페이지 레벨 JS만이 백그라운드에 반응 가능(스킬 §0-1).
- 음소거만 요청받아 스킬 §3의 두 번째 스크립트(가로 안내 로딩 문구)는 넣지 않음 — 방향 안내는 별개 관심사.
- 커밋 범위는 `export_presets.cfg`만 — 본편의 대량 `.import` 재저장 변경, 데모의 미추적 `reports/`·`tmp/`는 제외.

## 검증
- 데모판 `--headless --export-release "Web"` 실제 export(EXIT=0) → 생성된 index.html line 95(`</head>` 직전)에
  스크립트가 **원문 그대로**(`&&`·`<`·`>` 이스케이프 없이) 주입됨을 확인. cfg 파싱 + 주입 end-to-end 검증.
- 두 파일 head_include 라인이 동일하므로 본편도 동일 동작.
