## 결정 사항
- **적을 코어로 강제 유도하지 않는다(AI 무변경)** — `_find_player`를 쓰는 수십 개 경로를 재작성하는 리스크
  대신, "코어 dome 안 적 수만큼 드레인" + "플레이어가 코어 곁에 서면 적이 자연히 몰림"으로 방어 성립.
  최근 기믹 맵들의 '작은 프리미티브 1개' 패턴 유지.
- **침입 판정 = 수평 반경 + 지면 밴드** — 높은 발판 저격/드론이 코어를 안 깎게(dy로 제외) 해 "근접=코어 위협,
  원거리=플레이어 압박" 역할 분리를 자연히 구현. 반경만 쓰면 대각 거리로 저격도 걸려 역할이 뭉갬.
- **클리어=웨이브 전멸(ENEMY_CLEAR 재사용), 실패=코어 함락** — 기존 웨이브/아레나 클리어 로직 그대로 쓰고
  코어는 "실패 조건"만 얹음. 함락은 사망 경로(register_death→Death 씬 재시도) 재사용.
- **ARENA 배경은 전용 ambience로** — `_build_indoor_backdrop`가 HORIZONTAL 전용이라, ARENA 방어 맵의
  시그니처 배경은 `_ambience_reactor`에서 직접 그림(공유 게이트 무수정). [[new-map-always-full-background]].
- 검증: import(DefenseCore 등록) + 창모드 래퍼(`_core_check.tscn`) — (A) 실제 Stage 부팅으로 코어/웨이브/
  goal 생성 확인, (B) 격리 코어로 드레인·밴드 판정(수평/dy 밖 제외)·브리치·secured를 수동 `_physics_process`
  스텝으로 결정적 검증. 검증 후 임시 파일 삭제.

## 오류/함정 (known_issues 반영)
- **`bool(null)` = "Nonexistent 'bool' constructor" 크래시.** `bool()` 자체는 정상이나 인자가 null이면 죽는다.
  `Object.get("prop")`는 없는 속성에 default 없이 null 반환 → `bool(node.get("harmless"))`가 harmless 없는
  노드에서 크래시. `--import`는 통과, **창모드 부팅에서만** 잡힘(함수 본문 런타임 에러는 import가 놓침).
  → 존재 불확실 속성은 `if node.get("prop"):`(truthiness, null=falsy)로.

## 세션 2 — 사용자 피드백: 코요테/더블점프 + 외벽 옥상 저격 난이도

### 요약
플레이 피드백 2건 반영. ① "코요테 0.05로 줄였다는데 0.5초 뒤에도 공중 더블점프됨" — 코요테 값 문제가 아니라
가장자리 이탈이 점프를 소모 안 하던 게 원인. ② 외벽 옥상 저격수가 너무 쉽게 잡힘 — 둥지를 +20 올려 앞
발판서 서서 쏘면 발밑으로 빗나가게.

### 주요 변경
- `scripts/Player.gd`: `_physics_process` 공중 분기에 "코요테 소진 + jumps_used==0이면 jumps_used=1"(지상
  점프 소모 처리) 추가. 걸어서 떨어져 코요테(0.05s) 지나면 지상 풀점프는 못 쓰고 더블점프 1회만 남음.
  (사용자 선택: 지상 점프만 소모 / 공중 점프까지 전부 소모 중 전자.)
- `scripts/MapData.gd`(rooftops): 저격 둥지 2곳 발판+저격수 각 +20px 상향. 우측 (1150,1085→1065)/저격수
  1057→1037, 좌측 (130,645→625)/저격수 617→597. 앞 발판(ROOF 5/6) 총구선(원점−31=1072/632)이 저격수
  발(안착=발판 top)을 지나가 서서 쏘면 빗맞고, 점프로 높이를 맞춰야 명중.

### 결정 사항
- 코요테 값(0.05)은 정상 적용돼 있었고, 문제는 "걸어서 떨어짐=점프 미소모"라 공중 스택이 남던 것. 지상 점프를
  코요테 만료 시 소모 처리하는 게 표준 플랫포머 동작(더블점프는 스킬이라 1회 유지).
- 저격 난이도는 기하로 조정(known_issues "같은 높이면 발밑 통과"). Enemy._tick_sniper가 중력 적용해 저격수는
  발판 top에 안착 → 발판을 올리면 저격수 발이 총구선 위로 올라가 빗맞음. +20은 "살짝"이면서 확실히 플립(총구
  1072 vs 저격수 발 원래 1073 → 안착 후 1053, 19px 아래로 통과). 실플레이로 미세조정 가능.
- 검증: 창모드 — 코요테(안착 jumps_used=0/coyote0.05 → 이탈+2f 창 내 0 → +10f jumps_used=1/coyote0) 결정적
  통과. 저격 기하는 코드 검증(중력 안착). 맨 Control 씬은 창 포커스 상실 시 물리 스로틀 → 실제 Stage 부팅으로
  관찰(known_issues 후보). 검증 후 임시 파일 삭제.

### 미해결 / 다음 할 일
- 실플레이: 저격 +20이 "애매하게 안 맞음"으로 적절한지(과하면 12~16으로), 코요테 소모가 등반 리듬을 해치지
  않는지(외벽 옥상 더블점프 갭 도달성).

## 세션 3 — 모바일: 설정창 잘림 수정 + 입력 시 자동 전체화면

### 요약
사용자 피드백: ① 폰 설정창에서 닫기 버튼 아랫부분이 잘림 ② otherside처럼 입력 시 자동 전체화면 + 토글로 끄기.
설정 패널을 화면에 맞게 반응형으로 고치고, OrientationGuard의 1회성 전체화면을 "입력마다 재시도"로 확장 +
설정 토글 추가.

### 주요 변경
- `scripts/GameState.gd`: `auto_fullscreen`(기본 true) + load/save(display 섹션). SETTINGS_VERSION 불변
  (새 키는 get_value 기본값으로 하위호환).
- `scripts/OrientationGuard.gd`: `_input`을 1회성(`_lock_tried`)에서 "auto_fullscreen이면 입력(터치/클릭/키)
  마다 전체화면 아닐 때 재시도"로. `_enter_fullscreen`(웹=JS fullscreen+가로잠금 / 네이티브=터치기기만
  DisplayServer). `_try_web_landscape` JS에 `document.fullscreenElement` 가드(매 입력 호출돼도 무해).
- `scripts/Settings.gd`: (닫기 잘림) `_fit_to_viewport()` — 뷰포트 크기에 맞춰 패널 폭 캡 + 탭 최소높이 축소
  (내용이 패널 높이를 결정 → 항상 화면 안). 탭 내용을 `_scroll_wrap`(ScrollContainer, 탭 이름 보존)로 감싸
  짧은 화면서도 스크롤. `_process`/size_changed에서 재적용(content_scale_factor를 OrientationGuard가 프레임
  뒤 바꿀 수 있어). (토글) 화면 섹션에 "입력 시 자동 전체화면" CheckButton + `_on_auto_fullscreen_toggled`.

### 결정 사항
- **잘림 원인 = content_scale_factor 1.4에서 논리 화면(720/1.4≈514)보다 고정 패널(내용 ~641)이 큼.** 전체화면만
  으론 부족 → 패널을 뷰포트에 맞게 축소. `get_viewport_rect()`가 스케일을 반영(514)하므로 논리 공간에서 캡하면
  실제로도 맞음(검증: 1.4에서 패널 489<514, 1.7에서 398<424, 1.0 데스크톱 641<720 무회귀).
- **자동 전체화면은 웹(전체)+네이티브 터치기기.** 데스크톱 네이티브 키보드까지 매 입력 전체화면은 과해서 제외.
  1회성 대신 "전체화면 아니면 재시도"라 사용자가 빠져나가도 다음 입력에 복귀(otherside 방식). 토글로 끔.
- 검증: 창모드로 설정 패널을 scale 1.0/1.4/1.7에서 측정 — 전부 화면 안(닫기 보임), 토글 존재, auto_fullscreen
  기본 true 확인. 자동 전체화면 실동작(JS/orientation)은 폰 실측 대기(데스크톱은 is_touch_device=false).

### 미해결 / 다음 할 일 (모바일)
- ✅ **사용자 폰(안드로이드) 실측 OK** — 설정창 닫기 버튼 보임 + 자동 전체화면 잘 동작 확인.
- 남음: **iOS 미확인**(orientation.lock 미지원 → 세로 안내 폴백 경로만, 사용자 iOS 테스트 불가).
